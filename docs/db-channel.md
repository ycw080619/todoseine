# 数据库只读通道（可选）

Chat2Todo 的主路线是「导入导出文件」，不依赖任何客户端内部数据。
数据库只读通道是**可选项**：给愿意自己准备解密能力的用户用，默认关闭。

## 两条实现路径

| 后端 | 说明 | 需要什么 |
| --- | --- | --- |
| `community`（推荐） | 本项目以子进程调用社区已打通的解密工具，读取它的 JSONL 输出 | `[db].module` 指向可执行文件 |
| `builtin`（自建骨架） | 标准 SQLCipher 页面布局的读取器 | `[db].key` 或 `[db].key_file` |

两者都不可用时，`c2t db-import` 会给出 E4002 并提示改用导出文件，不会中断其它功能。

## 配置

```toml
[db]
enabled = true
path    = ""                          # 留空自动探测
module  = "C:/tools/nt_msg_util.exe"  # 社区解密工具
args    = ""                          # 传给它的额外参数
key     = ""                          # 内置读取器用；也可用环境变量 C2T_DB_KEY
key_file= ""
```

环境变量：`C2T_DB_MODULE`、`C2T_DB_ARGS`、`C2T_DB_KEY`。

## 社区工具的输出协议

工具接收一个参数（数据库路径），向 stdout 输出 **JSONL**，每行一条消息：

```json
{"timestamp": 1761300000, "sender": "1001", "sender_name": "小李", "content": "明天下午三点前把周报发我", "type": 0}
```

字段名宽松兼容：`content`/`text`、`timestamp`/`ts`、`sender`/`sender_id`、`sender_name`/`name`。
退出码非 0 或输出为空都会被视为失败（E4004）。

## 现状与限制

- 本机实测（QQ NT 9.9.31.49919）：库为 **1024 字节明文头 + 4096 字节页** 的腾讯 WCDB 变体；
- 标准 SQLCipher 的「口令 + PBKDF2」派生在本机未命中，内置读取器暂时覆盖不了它；
- 因此现阶段要真正读到消息，需要配置一个能解 WCDB 的社区工具。

## 安全检查

- 全程只读：不写 QQ 目录、不改原库、不注入进程；
- 自动探测只读注册表里的「文档」真实位置，避免被重定向后找错；
- 没有可用后端时不会静默假装成功，而是明确报错并给出下一步。
